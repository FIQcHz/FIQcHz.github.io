做了啥

起因：学完基础语法，总得干点什么

过完 Python：从入门到实践的语法之后，我就盯上了后面的实际项目的第一个，雷霆战机弱化版

我的目标很简单：做一个能 WASD 移动、按 J 键发射子弹、打外星人的非常普通 2D 小游戏，并且能打包成 exe 发给室友玩，顺便拿点情绪价值。

V1.0：一坨能跑起来的“面条代码”

首先，我借助 AI 神力，让ta教我我该干啥，然后每写一段（基本是抄的，毕竟第一次接触 pygame 库）。代码基本上都塞在一个巨大的 while True 里：

  • 飞船坐标用 ship_x、ship_y 两个全局变量。
  • 子弹用列表套字典管理。
  • 外星人用嵌套的 for 循环生成。
  • 碰撞检测写了一大堆 if。

它确实能跑，但每次想加新功能，我就得在混乱中找到我想要的代码，由于看着实在不是很舒服，我老早就想将其包装为类和函数了。

3. Bullets：弹药

踩坑实录：那些让我熬夜的 Bug

重构的过程中，我踩了几个极其经典的坑：

坑 1：pygame.Rect 只存整数，小数会被“吞”掉

我给外星人设了 self.speed = 0.5，想着它会慢慢往下飘。结果无论过多久，外星人都纹丝不动。
原因：Rect.x 和 Rect.y 只接受整数。50 + 0.5 存进去还是 50，小数直接被截断了。
解决方法：直接把速度改成整数 1 或 2。

坑 2：输入法把 WASD 吞了

游戏做好后，我发现按 WASD 飞船完全不动。查了半天代码，最后发现：是中文输入法拦截了按键。
解决：在 pygame.init() 之后加一句 pygame.key.stop_text_input()，直接告诉系统：这个窗口不需要打字，把输入法关掉。

坑 3：计时器忘了更新

做“无限生成外星人”时，我写了一个判断：if current_time - last_spawn_time > 2000:。
结果游戏开局后，无论我怎么改前面的间隔时间生成参数，外星人都像疯了一样每秒掉 60 个。
原因：我在生成之后，忘了写 last_spawn_time = current_time。导致第一次间隔时间过后的每一帧都满足“超过 2000 毫秒”的条件，无限触发。
解决：在生成完外星人之后，立刻更新计时器。

一开始直接打包，结果生成的 exe 一打开就闪退。后来发现如果只是简单的 PyInstaller 就只会打包代码，不会自动打包 ship.png 和 alien.png。

然后把所有 pygame.image.load("xxx.png") 改成 pygame.image.load(resource_path("xxx.png"))。

第三步：打包命令

  • -F：打包成单文件。
  • -w：去掉黑框（纯图形界面）。
  • --add-data "图片名;."：把图片也塞进 exe 里。

打包完成后，dist 文件夹里会躺着一个约 17MB 的 main.exe。把它单独发给任何人，双击就能玩。

想发网页版？被 CDN 卡住的绝望

为了让用手机的朋友也能玩，我尝试用 pygbag 把游戏编译成 WebAssembly 网页版，并部署到了 GitHub Pages。

结果网页一直卡在 “Loading, please wait…”。打开 F12 控制台一看：

Loading python interpreter from https://pygame-web.github.io/cdn/0.9.3/cpython312/main.data

它在下载几十 MB 的境外 CDN 资源，而国内网络根本下不动。

最后的破局方案：我放弃了 pygbag，直接让DSH帮我用 HTML5 + JavaScript 把游戏重写了一遍，并且把两张图片转成 Base64 编码，直接“焊”进了一个单独的 .html 文件里。

这个 1MB 的 HTML 文件，不需要服务器、不需要联网、不需要安装，发给朋友用手机浏览器打开就能玩，自带虚拟方向键和开火键。不过最后的结果不是很好，按键总是超出屏幕之外，而且每个浏览器打开时游戏流速还不一样

写在最后

这次从 Pygame 到 exe、再到 HTML 的折腾，让我最大的感悟是：

AI 是一个好帮手，只要你用好ta

通过 AI 学习，我的基本方法就是抄-注释-独立写-不会再抄-…
手动敲一遍，自己做好相应注释，不会的再问 AI，直到透彻为止
差不多学会后，就可以让 AI 出题，来考验自己。
能做的就自己做，不会的让 AI 示范，学完第二版再自己写。
